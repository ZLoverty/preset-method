## 2. P4 objectives

Implement a deterministic Chinese PDF build pipeline that:

1. Reads the existing English SOP Markdown.
2. Uses the existing production Pandoc reader settings.
3. Extracts P1 translation segments.
4. Resolves translations through P2 strict mode.
5. Reconstructs the translated Pandoc AST.
6. Validates structural integrity.
7. Renders a Simplified Chinese PDF.
8. Preserves images, tables, formulas, references and document structure.
9. Produces useful build diagnostics.
10. Fails safely when approved translations are incomplete.

No AI service may be invoked during a P4 build.

---

## 3. Non-negotiable principles

### Single source of truth

English Markdown is the only editable SOP source.

Do not create or maintain parallel Chinese Markdown files.

Do not modify English Markdown during translation or PDF generation.

Chinese content must come exclusively from approved P2 Translation Memory records.

### Deterministic translation

Given identical:

- English source
- Approved TM
- Glossary
- Build configuration
- Pandoc version
- TeX environment

The translated AST must be identical.

PDF byte-for-byte reproducibility is desirable but not guaranteed across different TeX environments.

Distinguish deterministic content from binary reproducibility.

### Fail closed

Official Chinese builds must fail if:

- A required translation is missing.
- A translation is not approved.
- Multiple approved translations are ambiguous.
- Placeholder rebinding fails.
- Protected content changes.
- AST validation fails.
- Required assets are missing.
- Pandoc or XeLaTeX rendering fails.

Never silently fall back to English prose in official Chinese builds.

### No AI during build

Do not call:

- Online translation APIs
- Local LLMs
- P3 translation providers
- Automatic draft generation
- Automatic approval operations

P4 consumes reviewed translations only.

Implement a reliable source AST assembly stage.

Suggested module:

`sop_i18n/build.py`

`sop/pdf-order.txt`

### Requirements

- Preserve source document ordering.
- Preserve headers and section hierarchy.
- Preserve tables and figures.
- Preserve raw Pandoc nodes.
- Preserve metadata required by the production PDF build.
- Preserve cross-document references.
- Preserve source-relative resource resolution.

### Important

If the English build concatenates Markdown before parsing, the Chinese build should normally parse the same assembled input before translating.

### Source mapping

Source mapping must not change the actual translated document structure.

## 8. Task P4.3 — Strict translation resolution

Use the existing P2 strict resolver.

Conceptual flow:

```python
source_ast = build_source_ast(...)
segments = extract_segments(source_ast)

translations = strict_resolve(
    segments,
    memory,
    language="zh-CN",
)

translated_ast = apply_translations(
    source_ast,
    segments,
    translations,
)

report = validate_translation(
    source_ast,
    translated_ast,
    segments,
)
```

Adapt names to actual implementation.

### Requirements

- Approved translations only.
- Complete segment coverage.
- Unique resolution.
- P2 placeholder rebinding.
- No source-language fallback.
- No draft or rejected translations.
- No automatic TM mutation.
- No automatic source synchronization that creates drafts.

### Failure report

When translation coverage is incomplete, report:

- Total segments
- Resolved segments
- Missing segments
- Draft-only segments
- Changed segments
- Ambiguous segments
- Invalid translations

Include source locations or occurrence IDs.

Do not proceed to PDF rendering if strict resolution fails.

### Acceptance criteria

- Empty production TM causes a clear build failure.
- Complete approved TM allows reconstruction.
- Changing an approved record to draft causes failure.
- Ambiguous translations cause failure.
- Placeholder mismatch causes failure.
- Build does not modify TM.

## 10. Task P4.5 — Chinese typography

Configure XeLaTeX for Simplified Chinese.

### Requirements

- Unicode Chinese rendering
- Reliable CJK line breaking
- Correct mixed Chinese/English typography
- Correct numerical and unit spacing
- Correct inline math rendering
- Correct bold and italic behavior where supported
- Proper headings and table text
- Stable image placement
- Readable page layout

### Font strategy

Prefer portable, explicitly configurable CJK fonts.

Do not hardcode a Windows-only font as the sole option.

Investigate available options such as:

- Noto Serif CJK SC
- Noto Sans CJK SC
- Source Han Serif SC
- Source Han Sans SC

Use an appropriate XeLaTeX CJK package, such as `xeCJK`, where compatible with the existing template.

Do not add conflicting CJK packages without checking the current template.

### Configuration

Support configurable CJK font names.

Provide clear errors when fonts are unavailable.

Document Windows and Linux setup.

### Font safety

Do not copy proprietary or system font binaries into the repository.

Do not bundle fonts without reviewing redistribution rights.

### Layout

Prefer preserving the English SOP's overall layout.

Allow Chinese-specific line-breaking and spacing adjustments where necessary.

Do not force identical page counts between English and Chinese PDFs.

## 11. Task P4.6 — Pandoc rendering

Render the validated Chinese Pandoc AST using the production PDF pipeline's compatible settings.

### Requirements

- Input format: Pandoc JSON AST
- Output: PDF
- Engine: XeLaTeX
- Chinese language metadata
- Correct resource paths
- Correct template/filter handling
- Correct image references
- Correct equation handling
- Correct table handling

### Important compatibility issue

Pandoc filters may behave differently depending on whether they run before or after translation.

Inspect the production pipeline and choose a consistent ordering.

Do not blindly apply all filters twice.

Document filter order explicitly.

### Resource resolution

Because the input is now a generated JSON AST rather than a Markdown file, relative resource paths may resolve differently.

Ensure that images and other resources still resolve correctly.

Do not solve this by permanently rewriting source Markdown paths.

### Output

Suggested:

`dist/sop-zh-CN.pdf`

Follow existing repository output naming conventions if they differ.

## 12. Task P4.7 — CLI and build entry point

Add a user-facing build command.

Suggested CLI:

```bash
python -m sop_i18n build \
  --language zh-CN \
  --order-file sop/pdf-order.txt \
  --memory i18n/memory/zh-CN.json \
  --output dist/sop-zh-CN.pdf
```

Optional flags:

```text
--check-only
--emit-ast
--report
--keep-intermediate
--cjk-mainfont
--cjk-sansfont
```

### Check-only mode

`--check-only` must:

- Assemble the source AST.
- Extract segments.
- Strictly resolve translations.
- Reconstruct translated AST.
- Validate structural integrity.
- Produce diagnostics.

It must not invoke XeLaTeX.

This mode is mandatory.

### Build behavior

- Nonzero exit code on failure.
- No partial output presented as successful.
- Do not overwrite an existing valid PDF with a failed build.
- Use temporary output files and atomic replacement where feasible.
- Preserve existing English build behavior.
- Do not modify TM.
- Do not modify Markdown.

### Script integration

Optionally add:

`scripts/build-pdf-zh.sh`

It should delegate to the Python CLI and avoid duplicating build logic.

Ensure it works in Git Bash and standard Linux shells.

## 14. Task P4.9 — PDF verification

After rendering, verify that the PDF is valid.

### Minimum checks

- Output file exists.
- Output file is nonempty.
- PDF signature is present.
- Pandoc/XeLaTeX exited successfully.
- No fatal LaTeX errors were ignored.

### Recommended checks

When tools are available:

- PDF page count
- Font embedding
- Missing-glyph warnings
- Broken image warnings
- LaTeX overfull boxes
- Missing references
- Basic text extraction

Do not treat an existing PDF in `dist/` as proof that the current build succeeded.

### Visual inspection

Create a manual visual QA checklist covering:

- Chinese glyphs
- Headers and footers
- Tables
- Figures
- Equations
- Page breaks
- Captions
- Cross-references
- Mixed Chinese/English text

Do not claim visual verification without inspecting the rendered result.
